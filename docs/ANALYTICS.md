# Аналитика

Агрегаты считает backend по всей БД. Клиент: `src/api/analytics.ts`. Контракт полей и query — [API.md](API.md). Скриншоты и DOCX: [SOKOL_Аналитика.docx](SOKOL_Аналитика.docx), [analytics-screenshots/](analytics-screenshots/). Генерация из `sokol-frontend`: `npm run docs:analytics-tz:full`.

| Раздел | Endpoint | Период | Фильтры UI |
|--------|----------|--------|------------|
| Проверки | `/analytics/checks` | `start_date` | год, квартал, аудиторы, департаменты |
| Рекомендации | `/analytics/recommendations` | `deadline` | то же |
| Мониторинг | `/analytics/monitoring` | `deadline` | то же |
| ДВА | `/analytics/dva` | оба поля | то же |
| Планирование | `/analytics/planning` | `start_date` | год, квартал, департаменты, без аудиторов |

Месяц есть в API, в сайдбаре нет. Фильтр департамента — `audit_object.overlap`. Фильтр аудиторов на проверках: `check_leader` или аудитор связанной рекомендации. Фильтры статуса и существенности backend принимает, UI не показывает.

`/analytics` — два ряда вкладок (Проверки / Рекомендации, Мониторинг / ДВА). Посещённые панели остаются смонтированными. Каркас `AnalyticsDashboardFrame`: сайдбар `lg:w-80`, сетка `react-grid-layout` без drag, KPI «Итого» над сеткой. `staleTime` 60 с.

Экспорт вкладки из сайдбара — снимок DOM (html / pdf / docx / xlsx). На карточке: «В конструктор», PNG в буфер, fullscreen. Кнопка «Добавить в конструктор (N)» кладёт отмеченные карточки на текущий лист, это не экспорт вкладки.

Карточки, которых нет в ответе API как отдельных виджетов, здесь не перечислены — блоки ответа см. в API.

- **Проверки.** Карта департаментов — уникальные ключи проверок, у которых есть рекомендация с этим объектом аудита. Несколько рекомендаций одного ключа на один департамент считаются один раз; ключ с несколькими департаментами входит в каждый. KPI: всего, запланировано, в процессе, завершено, доля завершённых.
- **Рекомендации.** Динамика по существенности, матрица, виды, карта ТОП-10. KPI: всего, в процессе, не решено, исполнено, доля исполненных.
- **Мониторинг.** Статусы, доп. статусы, переносы по проверкам, исполнено в ходе аудита, матрица. KPI: исполнено, в работе, на контроле, срок нарушен, доля просроченных.
- **ДВА.** Существенность и доп. статус по сотрудникам, доля «не решено», карта проверок, жизненный цикл (приказ → программа → АЗ → ДЗ). «Средняя продолжительность проверки» — то же среднее, что подпись графика жизненного цикла: календарные дни от первого заполненного этапа (приказ, программа, АЗ, ДЗ) до последнего. В выборку входят проверки, где заполнены хотя бы два этапа. «Начало» и «Окончание» не участвуют. Столбцы аудиторов обрезаются до `DVA_AUDITOR_BAR_LIMIT = 12`. Часть API (treemap, `auditorDocuments`, `portfolioSeries`) на вкладке не рисуется и доступна через конструктор. Lifecycle сортируется по `totalDays` desc; DOCX отдаёт табличные строки, не только снимок DOM.
- **Планирование.** Фильтр департаментов на список неохваченных не влияет. «Не указан» в неохваченные не входит. Список пересчитывается при смене года и квартала. KPI: охват, с проверками, не охвачено, красные рекомендации. Метки limited/beta нет. Visual export включён.

## Конструктор

`/constructor` только на клиенте. Библиотека `{ dashboards, activeDashboardId }` в `localStorage` (`sokol.constructor.library.v1`). Старый ключ `sessionStorage` мигрирует в «Черновик».

Виджет — снимок (`kind`, `sectionId`, фильтры, payload, layout), не live-запрос. Один график можно положить несколько раз с разными фильтрами. Источники: checks, recommendations, monitoring, dva, planning. Запись в localStorage сразу, кнопки «Сохранить» нет. Экспорт листа: HTML и PDF (снимок смонтированного холста); из истории без открытия листа снимок пустой.

Серверного `POST /dashboards` нет: виджет не перезапрашивает агрегаты.

## Ограничения

Drill-down и сохранённые серверные отчёты нет. Наблюдения в аналитике не участвуют. HTML-экспорт хрупок на карточках вне экрана.
