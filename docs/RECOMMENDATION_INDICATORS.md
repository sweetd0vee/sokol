# Автостатус рекомендаций

Два значка в таблице и на форме считаются правилами, не вручную. Одна и та же логика на backend и frontend. Менять только оба compute-модуля, тесты и эту страницу.

| Слой | Файл |
|------|------|
| Python | `app/services/recommendation_status.py` (`choose_status_pair`) |
| Карточка и превью АЗ | `recommendationAutoStatus.ts`, `recommendationFormAutoStatus.ts`, `checkRecommendationsPreview.ts` |
| Запись и ночной прогон | `overlay_computed_status_fields`, `recommendation_status_refresh.py` |
| Иконки | `indicatorIcons.ts` |

Тесты: `test_recommendation_status.py`, `recommendationAutoStatus.test.ts`, `recommendationFormAutoStatus.test.ts`. Общий набор кейсов — [fixtures/auto_status_golden.json](fixtures/auto_status_golden.json).

Календарный день — Europe/Moscow, сравнение `YYYY-MM-DD` без времени. Автоматика всегда пишет пару `status`+`indicator` и `additional_status`+`additional_indicator`. Колонка `execution_deadline` не читается: срок исполнения — только `actual_completion_date`.

| Поле | Смысл |
|------|--------|
| `deadline` | Срок контроля. Перенос **перезаписывает** его самой поздней датой |
| `actual_completion_date` | Срок исполнения |
| `deadline_extensions` | Переносы (дата + комментарий), плюс legacy `extension_1_date` / `extension_2_reason` |
| `control_removals` | Снятие с контроля, плюс legacy `remove_from_control_*` |

Пустой JSON переноса не считается. KPI «с переносами» считает и `extension_2_reason`.

## Пары

| Правило | status / indicator | additional |
|---------|--------------------|------------|
| Открыта, срок контроля в будущем | `on_control` / серые часы | серый колокольчик |
| Открыта, срок сегодня или раньше | `in_progress` / жёлтые часы | жёлтый колокольчик |
| Исполнено не позже контроля | `completed` / зелёная галочка | `on_time`, зелёный |
| Исполнено позже контроля | `completed` / зелёная галочка | `deadline_violated`, красный |
| Снято с контроля | `unresolved` / красный треугольник | красный колокольчик |
| В АЗ «исполнено в ходе аудита» | `completed` / синяя звезда | зелёный колокольчик |

## Приоритет

Считается первое совпавшее:

1. Заполнено «снять с контроля» (дата или непустой комментарий) → красная пара, даже если есть срок исполнения или звезда.
2. Индикатор «исполнено в ходе аудита» → звезда и зелёный колокольчик.
3. Есть оба срока: исполнение позже контроля → галочка и красный колокольчик; иначе галочка и зелёный.
4. Есть только срок контроля: сегодня раньше него → серая пара; сегодня равно или позже → жёлтая пара.
5. Иначе автоматика ничего не пишет.

Перенос — не отдельная пара, а подмена `deadline` до шагов 3–4. Берётся максимальная дата среди `deadline_extensions` и legacy-полей. Порядок строк не важен. Комментарий без даты срок не двигает. Пустая заготовка строки снятия на форме не считается.

## Когда пересчитывается

Смена срока или контрольной зоны на форме, create/PATCH (любое поле, в том числе только `name`), превью импорта из АЗ, каждый день в 00:05 Europe/Moscow. `SOKOL_STATUS_SCHEDULER=0` выключает ночной цикл; в pytest он выключен всегда. Текущие статусы от пересчёта не защищены, кроме шага 2, пока звезда на месте и снятия нет.

Импорт: фраза «исполнено в ходе аудита» или «исправлено в ходе аудита» в сроке → шаг 2 и пустой `deadline`; дата в будущем → серая пара; дата сегодня или в прошлом → жёлтая. После `batch` backend прогоняет overlay ещё раз.

## Сценарии

1. Срок 15.10.2026, сегодня 28.09.2026 → серые. Ночью 16.10 → жёлтые.
2. Исполнение 10.10 при контроле 15.10 → зелёная галочка и зелёный колокольчик.
3. Исполнение 20.10 при контроле 15.10 → галочка и красный колокольчик.
4. Два переноса, 01.10 и 01.12, в любом порядке → `deadline=01.12`, снова серые, пока дата не наступит.
5. «Снять с контроля» после исполнения или вместо даты в АЗ «исполнено в ходе аудита» → красная пара. Снятие перебивает звезду.
