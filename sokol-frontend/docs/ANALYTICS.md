# Аналитика

Раздел `/analytics` — аналитическая витрина SOKOL. Агрегации считаются на backend по всей БД (без лимитов list API).

## API

| Вкладка | Endpoint |
|---|---|
| Проверки | `GET /api/v1/analytics/checks` |
| Рекомендации | `GET /api/v1/analytics/recommendations` |
| Мониторинг | `GET /api/v1/analytics/monitoring` |
| ДВА | `GET /api/v1/analytics/dva` |

Планирование (отдельный раздел `/planning`): `GET /api/v1/analytics/planning` — см. [PLANNING.md](PLANNING.md).

Клиент: `src/api/analytics.ts`. Query (повторяемые списки): `granularity`, `years`, `quarters`, `months`, `auditors`, `departments`.  
Для рекомендаций/мониторинга API также принимает `statuses`, `additionalStatuses`, `materialityLevels` — в UI эти фильтры не выводятся.

Ответ — KPI/серии + `filterOptions` (аудиторы, департаменты, `anchorDates`). Поля в camelCase. Требуется Bearer JWT.

## Общая логика UI

- Два ряда вкладок: «Проверки» / «Рекомендации» и «Мониторинг» / «ДВА».
- Каркас: `AnalyticsDashboardFrame` — боковая панель фильтров (`lg:w-80`) + сетка карточек.
- Сетка: `react-grid-layout`, карточки `static` (без drag-and-drop). Сводка KPI («Итого») над сеткой.
- Фильтры периода в UI: **год / квартал** (месяц есть в API, в сайдбаре не показывается). Плюс аудиторы и департаменты.
- Сначала bootstrap-запрос (`granularity=year`, staleTime 60s), затем перезапрос при смене фильтров.
- Периодичность графиков = выбранный срез (год/квартал).
- Экспорт — визуальный снимок выбранных карточек (html / pdf / docx / xlsx); секции переключаются на карточках. Метаданные — из ответа API.

## Конструктор

Сборка отчётных листов вынесена в отдельный раздел `/constructor` — [CONSTRUCTOR.md](CONSTRUCTOR.md).

На вкладках Проверки / Рекомендации / Мониторинг / ДВА отметить графики галочкой и нажать **В конструктор**. Снимок с текущими фильтрами попадает на *текущий* дашборд в истории конструктора.

Бизнес-описание дашбордов со скриншотами: [SOKOL_Аналитика.docx](SOKOL_Аналитика.docx) (`npm run docs:analytics-tz:full`).

## Вкладка «Проверки»

Период по `start_date` проверки. Департаменты — через связанные рекомендации (`audit_object`).

Карточки: Итого, Количество проверок, Виды проверок, Типы проверок, Карта департаментов (ТОП-10), Оценка эффективности.

KPI: Всего, Запланировано, В процессе, Завершено, Доля завершённых.

## Вкладка «Рекомендации»

Период по `deadline`.

Карточки: Итого; Существенность (donut + столбцы по периодам в одной карточке); Матрица существенности; Статусы по периодам; Карта департаментов (ТОП-10).

KPI: Всего, В процессе, Не решено, Исполнено, Доля исполненных.

## Вкладка «Мониторинг»

Тот же источник, что рекомендации; срез по исполнению сроков.

Карточки: Итого, Статусы, Дополнительные статусы, Перенос срока, Исполнено в ходе аудита, Матрица статусов.

KPI: Исполнено, В работе, На контроле, Срок нарушен, Доля просроченных.

## Вкладка «ДВА»

Объединяет проверки (`start_date`) и рекомендации (`deadline`).

Карточки: Итого; Карта сотрудников по проверкам / рекомендациям; Импакт рекомендаций; Результативность исполнения; Своевременность; Документная дисциплина.

KPI: Проверки, Рекомендации, Сотрудники, Высокая существенность, Исполнение, Нарушение сроков.

## Ограничения

- Drill-down API и сохранённые серверные отчёты не реализованы.
- Наблюдения пока не участвуют в аналитике.
- Фильтры статусов/существенности в UI отсутствуют, хотя backend их принимает.
