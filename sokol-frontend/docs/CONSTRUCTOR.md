# Конструктор дашбордов

Раздел `/constructor` — сборка отчётных листов из графиков **Аналитики** и **Планирования**.

Это задел: история и холст живут на клиенте (`localStorage`). Серверного CRUD пока нет.

## Зачем отдельный раздел

Раньше конструктор был вкладкой внутри аналитики и держал один безымянный лист в `sessionStorage`. Теперь это соседний пункт сайдбара с несколькими именованными дашбордами: создать, править, сохранить копию, экспортировать, удалить.

## Сценарий

1. **Создать** — `/constructor` → «Создать дашборд» → имя → пустой холст `/constructor/:id`. Лист становится *текущим*: сюда попадают новые графики.
2. **Набрать графики** — на «Аналитика» / «Планирование» отметить карточки галочкой (**«В конструктор»**) и нажать **«Добавить в конструктор (N)»**. Снимок текущего вида и фильтров кладётся на текущий лист. Один график можно добавить несколько раз (разные фильтры).
3. **Редактировать** — карандаш в истории или имя строки. На холсте: переставить, растянуть, удалить блоки, переименовать лист, очистить; действия **«Сделать текущим»**, **«Переименовать»**, **«К списку дашбордов»**.
4. **Сохранить** — лист пишется в `localStorage` сразу после любого изменения (добавление, удаление, layout, переименование, очистка). Отдельной кнопки «Сохранить» на холсте нет. **«Копировать»** в меню строки — копия с новым именем (модалка «Копировать»).
5. **Экспорт** — на холсте: HTML / PDF / DOCX / XLSX (визуальный снимок сетки). Из истории «Экспорт» открывает тот же холст: снимок снимается с DOM, без открытого листа экспортировать нельзя.

Если листа ещё нет, первое добавление в конструктор само создаёт черновик в истории.

Метка **Текущий** в таблице — дашборд, который принимает новые графики.

Планирование имеет собственный visual export вкладки **и** отправку карточек в конструктор.

## Модель

```ts
type ConstructorDashboardRecord = {
  id: string;
  name: string;
  createdAt: string;  // ISO
  updatedAt: string;
  widgets: ConstructorWidget[];  // снимок графика + layout
};
```

Библиотека: `{ dashboards, activeDashboardId }` в `localStorage` (`sokol.constructor.library.v1`). Старый ключ `sokol.analytics.constructor.v1` (`sessionStorage`) мигрирует в дашборд «Черновик».

Провайдер `AnalyticsConstructorProvider` поднят на уровень приложения, чтобы аналитика, планирование и конструктор делили одну библиотеку.

Виджет — **снимок**, не live-запрос. Смена фильтров на исходной вкладке уже добавленный блок не меняет.

## Как лучше довести до продукта

### Создать

Сейчас: модалка имени → запись в библиотеке → переход на холст.

Дальше:

- `POST /api/v1/dashboards` `{ name }` → `{ id, name, createdAt, widgets: [] }`.
- Не класть тяжёлые payload графиков в URL.
- Черновик без имени допустим, пока пользователь не нажал «Сохранить» с названием.
- Не плодить пустые листы: если уже есть пустой текущий — открывать его, а не создавать второй.

### Редактировать

Сейчас: `react-grid-layout` (12 колонок), drag за ручку, resize, удаление карточки, переименование.

Дальше:

- `GET /api/v1/dashboards/:id` при входе на холст.
- `PATCH` layout debounce 300–500 мс после `onLayoutChange`, не на каждый пиксель.
- Не хранить Recharts-дерево: только `kind + sectionId + filterSnapshot + layout`. При открытии листа перезапрашивать агрегаты аналитики/планирования с сохранёнными фильтрами — лист не устареет. Нынешний полный payload оставить как fallback / офлайн-кэш.
- Опционально: подпись блока, скрыть легенду, зафиксировать размер.

### Сохранить

Сейчас холст без кнопки «Сохранить»: `updatedAt` и `localStorage` обновляются в том же мутаторе, что меняет виджеты или layout.

Дальше, когда появится API:

| Действие | Смысл |
|---|---|
| **Автосохранение** | Debounced `PUT /dashboards/:id` после add/remove/layout/rename. На UI можно показать тихий статус «Сохранено», без отдельной кнопки. |
| **Копировать** | `POST` копии с новым именем. История не перезаписывается. |

Dirty: любое add/remove/layout/rename после последнего успешного ответа сервера. Конфликт (лист изменили в другой вкладке) — `updatedAt` / ETag, диалог «перезаписать / взять с сервера».

### Экспорт

Сейчас: `exportConstructorDashboard` — html-to-image по смонтированному холсту.

Дальше не делать «тихий» экспорт из таблицы истории: без DOM снимок пустой. Варианты:

1. Открыть холст и сразу вызвать экспорт (как сейчас через пункт меню).
2. Серверный отчёт: JSON виджетов + агрегаты → PDF/DOCX на backend (стабильнее html-to-image).
3. Кэш последнего файла экспорта на записи дашборда — только если лист не менялся.

Форматы оставить те же, что у аналитики: HTML, PDF, DOCX, XLSX.

## Ограничения задела

- Нет API, шаринга, прав, папок, серверного пересчёта по фильтрам.
- Экспорт из истории требует открытого холста.
